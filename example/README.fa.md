# فروشگاه نمونه

[English](README.md)

سفارش‌هایی که مشتری‌ها در یکی از دو شعبه ثبت می‌کنند و کارکنان آن‌ها را مدیریت
می‌کنند - و فقط بعضی از کارکنان قیمت را می‌بینند. همه‌ی لایه‌های کتابخانه در این
پروژه هست، هر کدام در همان فایلی که در یک پروژه‌ی واقعی می‌گذارید:

| چه چیزی | کجا |
|---|---|
| backend، مجوز پیش‌فرض DRF، فایل `ACCESS` | `config/settings.py` |
| بسته‌ها و نقش‌ها، به صورت کد | `config/access.py` |
| مجوزها، یک فیلد محافظت‌شده (`price`)، یک اکشن وضعیت (`approve`) | `shop/models.py` |
| دو دامنه‌ی ردیف در کد: `own` و `branch` | `shop/querysets.py` |
| قانونی که هیچ مجوزی نمی‌تواند بگوید: سفارش تحویل‌شده هیچ‌وقت ویرایش نمی‌شود | `shop/policies.py` |
| API، و یک اکشن که در کد پیدا می‌شود (`print_invoice`) | `shop/api.py` |
| صفحه‌های خود Django، با همان قانون‌ها | `shop/views.py` |
| پنل ادمین، بدون هیچ کدی درباره‌ی دسترسی | `shop/admin.py` |
| نتیجه‌ی همه‌ی این‌ها برای هر شخص | `shop/tests.py` |

## اجرا

از ریشه‌ی مخزن، با کتابخانه نصب‌شده در یک محیط تازه:

```bash
python -m venv .venv && .venv/bin/pip install -e '.[drf]'
```

```bash
cd example
```

```bash
../.venv/bin/python manage.py migrate
```

`migrate` فایل `config/access.py` را هم اعمال می‌کند (`SYNC_ON_MIGRATE`). بعد
افراد و سفارش‌های نمونه را بسازید، و یک ابرکاربر برای صفحه‌های دسترسی:

```bash
../.venv/bin/python manage.py example_data
```

```bash
../.venv/bin/python manage.py createsuperuser
```

```bash
../.venv/bin/python manage.py runserver
```

رمز هر کاربر نمونه همان نام کاربری اوست - هرگز روی یک پایگاه داده‌ی واقعی.

| ورود با | نقش یا بسته | به چه می‌رسد |
|---|---|---|
| `north_manager` | نقش *Branch manager* | سفارش‌های شعبه‌ی North: دیدن، ویرایش، تأیید، چاپ - هیچ‌وقت قیمت |
| `south_manager` | نقش *Branch manager* | سفارش‌های South، به همین شکل |
| `accountant` | بسته‌ی *Accountants* | همه‌ی سفارش‌ها، با قیمت؛ بدون هیچ تغییری |
| `alice`، `bob` | نقش *Customer* | سفارش‌های خودشان؛ ثبت سفارش تازه، بدون قیمت‌گذاری یا تأیید |

در `/admin/` وارد شوید، بعد `/orders/` و `/api/orders/` را باز کنید. ابرکاربر
صفحه‌های دسترسی را زیر *Access* می‌بیند: بسته‌ها به شکل جدول، وضعیت هر شخص،
سازنده‌ی قانون، فیلدهای محافظت‌شده، اکشن‌ها و نقش‌ها. اگر زبان مرورگر را *فارسی*
بگذارید، این صفحه‌ها فارسی و راست به چپ می‌شوند.

## چند چیز برای امتحان

* با `north_manager` چراغ مطالعه (Desk lamp) را تأیید کنید - بعد دوباره تأییدش
  کنید: تأیید فقط از *pending* نوشته می‌شود.
* با `south_manager` فرش (Rug) را ویرایش کنید: تحویل شده، پس policy رد می‌کند.
* با `alice` این را به `/api/orders/` بفرستید:
  `{"branch": 1, "item": "Clock", "price": "1.00"}` - پاسخ، قیمت را فیلدی
  می‌داند که او اجازه‌ی نوشتنش را ندارد.
* با ابرکاربر یک دامنه‌ی قانونی برای سفارش‌ها بسازید - *status* *is* *pending* -
  و به کسی بدهید. *price* را هم امتحان کنید: هیچ قانونی فیلد محافظت‌شده را
  نمی‌خواند، چون به دارنده‌اش می‌گوید آن فیلد چه مقداری دارد. بسته‌ای که فایل
  `ACCESS` نام می‌برد فقط‌خواندنی است: در فایل تغییرش دهید و
  `python manage.py clearance_sync --dry-run` را اجرا کنید.
* `python manage.py clearance_check` - چیزهایی در پایگاه داده که هیچ دسترسی‌ای
  نمی‌دهند، یا شاید منظور نبوده‌اند.
